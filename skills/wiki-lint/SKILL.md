# 위키 점검 (Lint)

## 볼트 찾기

1. 세션 컨텍스트의 `LLM 위키 볼트:` 줄(플러그인 SessionStart 훅이 주입하거나 CLAUDE.md에 있음) → 그 절대경로
2. 없으면 `~/.claude/llm-wiki/vault-path` 파일 첫 줄
3. 없으면 현재 디렉터리가 볼트인지 — 루트에 `AGENTS.md`(또는 `CLAUDE.md`)와 `wiki/index.md`
4. 모두 아니면 멈추고 `wiki-init`을 권한다

이하 `<VAULT>`는 그 절대경로다. 아래 셸 예제는 전부 `cd "<VAULT>"` 한 뒤 실행한다.
형식 규격(`type`·`domain` 허용값 등)은 `<VAULT>/AGENTS.md`(없으면 `CLAUDE.md`)가 기준이다.

## 핵심 원칙

**위키가 커져도 건강을 유지하게 만든다.** 사람들이 위키를 포기하는 이유는
유지 관리 부담이 가치보다 빠르게 커지기 때문이다. 그 부담이 당신 몫이다.

점검은 **보고서를 내는 일**이지 마음대로 고치는 일이 아니다.
기계적으로 명백한 것만 바로 고치고, 판단이 필요한 것은 사용자에게 묻는다.

## 언제 쓰지 않는가

- 새 자료 수집 → `wiki-ingest`
- 질문에 답하기 → `wiki-query`

## 점검 항목

### 1. 모순 (최우선)

`status: contested` 페이지를 전부 훑는다. 그리고 아직 표시되지 않은 모순을 찾는다 —
같은 개체·개념을 다루는 페이지들이 서로 다른 말을 하는 경우.

발견하면 양쪽에 `contested`를 달고 사용자에게 **어느 쪽이 맞는지 묻는다.**
임의로 판정하지 않는다.

### 2. 낡은 주장

새 자료에 의해 대체된 서술. `sources`가 가리키는 자료보다 나중에 들어온
자료가 같은 주제를 다루는데 반영되지 않은 경우.

### 2-1. 뒤집힌 결정 미표시

나중 페이지가 옛 페이지의 결정을 바꿨는데(제거·전환·되돌림·교체·정정) 옛 페이지에
`superseded_by`나 경고가 없는 경우. 새 세션이 폐기된 결정을 현재 사실로 읽어 가는 주원인이다.
규칙은 `<VAULT>/AGENTS.md`의 "뒤집힌 결정".

```bash
# 후보 추출 — 옛 페이지를 링크하면서 바뀜을 뜻하는 낱말을 함께 쓴 줄
KW='제거|전환|되돌|철회|폐기|대신|교체|취소|뒤집|더 이상|바꿨|폐지|대체|정정|번복|원복|롤백|틀렸|아니었'
grep -rnE "\[\[[^]]+\]\].*($KW)|($KW).*\[\[[^]]+\]\]" wiki/ --include='*.md' \
  --exclude=index.md --exclude=log.md
```

키워드로 뽑은 후보라 **대부분 오탐이다** — 옛 페이지 제목에 '제거'가 들어 있을 뿐이거나,
나중 페이지가 옛 결정을 이어받아 쓰는 경우. 후보마다 링크된 페이지가 **더 이른 날짜**이고
아직 표시가 없는지 확인한 뒤, 두 페이지를 읽고 판정한다.

- **핵심 결정이 뒤집힘(FULL)** → `superseded_by` + 경고 + 인덱스 `⤳ 뒤집힘:` 표시 제안
- **일부 문장만(PARTIAL)** → 그 문장 취소선 + `(→ …)` 제안
- 애매하면 표시하지 않는다. **과잉 표시가 미표시보다 해롭다** — 유효한 결정을 폐기된 것으로 읽게 만든다.

표시 자체는 판단이 들어가므로 목록을 보여 주고 승인받은 뒤 단다. 옛 페이지 본문은 고치지 않고, 지우지 않는다.

`superseded_by`가 가리키는 페이지가 실제로 있는지, 인덱스 줄에 표시가 있는지도 함께 본다 — 이건 바로 고친다.

### 3. 고아 페이지

유입 링크가 없는 페이지. 다른 어떤 페이지도 `[[링크]]`로 가리키지 않는 것.

```bash
# 후보 추출 — 파일명이 위키 어디에도 링크로 등장하지 않는 페이지
# index.md·log.md 는 제외한다. 인덱스는 모든 페이지를 링크하므로
# 포함시키면 고아가 하나도 잡히지 않는다.
for f in wiki/*/*.md; do
  n=$(basename "$f" .md)
  grep -rqF "[[$n]]" wiki/ --exclude=index.md --exclude=log.md || echo "orphan: $f"
done
```

고아라고 다 문제는 아니다. 최근 수집분은 아직 연결이 안 걸렸을 수 있다.
**어디에 연결하면 좋을지 제안한다.**

`wiki/sessions/`는 본질적으로 `index.md`·`log.md`에서만 링크되므로 **거의 항상
고아로 잡힌다.** 매번 보고하지 않는다. 등장한 개체·개념 페이지가 볼트에 있는데도
연결이 없을 때만 지적한다.

### 4. 없는 페이지 (깨진 링크 / 언급만 되는 개념)

`[[X]]`로 링크됐지만 파일이 없는 경우, 그리고 여러 페이지에서 반복 언급되는데
자체 페이지가 없는 중요 개념.

```bash
# 깨진 링크 후보
# awk 가 코드블록을 걷어낸다 — 문서 안 예제의 [[...]] 를 링크로 오인하지 않도록.
# 대상 탐색은 볼트 전체에서 한다 — 볼트 루트에 있는 파일도 링크될 수 있다.
find wiki -name '*.md' ! -name 'index.md' \
  -exec awk 'FNR==1{f=0} /^```/{f=!f; next} !f' {} + \
  | grep -o "\[\[[^]]*\]\]" | sort -u | tr -d '[]' | while read -r n; do
      find . -path ./.git -prune -o -path ./.obsidian -prune -o -name "$n.md" -print \
        | grep -q . || echo "missing: $n"
    done
```

### 5. 누락된 상호 참조

A가 B를 언급하는데 링크가 없거나, B에서 A로 돌아오는 연결이 없는 경우.
이건 **바로 고쳐도 되는 항목**이다.

### 6. 프론트매터 위생

`sources`가 빈 페이지, `updated`가 실제 수정일과 어긋난 페이지,
`type`·`domain`이 규격 밖인 페이지. 바로 고친다.

### 7. 아이디어 낡음 (`wiki/ideas/`)

`idea` 페이지의 "현재 상태"는 특정 커밋 시점의 코드 서술이라 **가장 빨리 낡는다.**

- `updated`가 오래된 항목 — 대상 코드가 그 사이 바뀌었을 수 있다
- `stage: 진행`인데 몇 달째 그대로인 항목
- `targets`가 비었거나 존재하지 않는 페이지를 가리키는 항목
- 이미 구현됐는데 `완료`로 안 바뀐 항목

```bash
grep -rn "^updated:\|^stage:" wiki/ideas/ | paste - -
```

임의로 `완료` 처리하지 않는다. **사용자에게 묻는다.**

### 8. 데이터 공백 — 다음에 무엇을 할지

위키가 답하지 못하는 명백한 질문, 웹 검색이나 추가 자료로 메울 수 있는 구멍.
**조사해볼 만한 질문과 찾아볼 자료를 제안한다.** 점검에서 가장 값어치 있는 산출물이다.

## 보고 형식

```markdown
## 점검 결과 (YYYY-MM-DD)

**바로 고침**
- 누락 상호참조 4건: [[A]]↔[[B]] ...
- 프론트매터 `updated` 어긋남 2건

**판단 필요**
- 모순 1건: [[A]]는 X라 하고 [[B]]는 Y라 함 — 어느 쪽입니까?
- 고아 3건: [[C]] ... — [[D]]에 연결하면 어떨까요?

**제안**
- [[E]]가 반복 언급되는데 페이지가 없음 — 만들까요?
- 공백: Z에 대한 자료가 없음 — <구체적 자료> 수집 제안
```

### 로그

```
## [YYYY-MM-DD] lint | 상호참조 4건 보완, 모순 1건 제기
```

## 빠른 참조

| 항목 | 조치 |
|---|---|
| 모순 | `contested` 표시 + **사용자에게 판정 요청** |
| 낡은 주장 | 갱신 제안 |
| 뒤집힌 결정 미표시 | 판정 목록 제시 → **승인 후** `superseded_by`·경고·인덱스 표시 |
| `superseded_by` 대상 없음·인덱스 표시 누락 | **바로 고침** |
| 고아 페이지 | 연결처 제안 |
| 깨진 링크 | 페이지 생성 제안 |
| 누락 상호참조 | **바로 고침** |
| 프론트매터 오류 | **바로 고침** |
| 낡은 아이디어 | 재확인 제안. **임의로 완료 처리 금지** |
| 데이터 공백 | 조사 질문·자료 제안 |

## 흔한 실패

| 실패 | 결과 |
|---|---|
| 모순을 임의로 판정 | 근거 없이 한쪽을 사실로 굳힘 |
| 고아 페이지를 삭제 | 사용자 자산 소실. **삭제는 절대 하지 않는다** |
| 키워드 후보를 판정 없이 전부 `superseded_by` 처리 | 유효한 결정까지 폐기된 것으로 읽힘 |
| 뒤집힌 옛 페이지를 지우거나 보관 폴더로 옮김 | 링크가 깨지고 "왜 바꿨나"가 사라짐 |
| 전부 자동으로 고침 | 사용자가 위키를 통제하지 못하게 됨 |
| 문제만 나열하고 끝 | 8번(다음에 뭘 할지)이 가장 값어치 있다 |
| 점검 결과를 `log.md`에 안 남김 | 언제 점검했는지 추적 불가 |

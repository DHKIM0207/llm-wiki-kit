# 자료 수집 (Ingest)

## 볼트 찾기

1. 세션 컨텍스트의 `LLM 위키 볼트:` 줄(플러그인 SessionStart 훅이 주입하거나 CLAUDE.md에 있음) → 그 절대경로
2. 없으면 `~/.claude/llm-wiki/vault-path` 파일 첫 줄
3. 없으면 현재 디렉터리가 볼트인지 — 루트에 `AGENTS.md`(또는 `CLAUDE.md`)와 `wiki/index.md`
4. 모두 아니면 멈추고 `wiki-init`을 권한다

이하 `<VAULT>`는 그 절대경로다. 볼트 밖에서도 호출되므로 **모든 경로를 절대경로로 쓴다.**
페이지 형식·불변 규칙은 `<VAULT>/AGENTS.md`(없으면 `CLAUDE.md`)를 따른다 — 여기서 복제하지 않는다.

## 핵심 원칙

자료를 읽고 **핵심 정보를 추출해 기존 위키에 통합한다.** 요약 페이지 하나를
던져놓고 끝내는 것이 아니다. 자료 하나가 10~15개 페이지를 건드릴 수 있다.

색인만 만드는 것과 통합하는 것의 차이가 이 위키의 전부다.

## 언제 쓰지 않는가

- 위키에 **질문**할 때 → `wiki-query`
- 위키 **건강 점검** → `wiki-lint`
- 코딩 에이전트 작업 자체를 기록할 때 → `wiki-log`

## 절차

### 1. 자료 확인

`<VAULT>/raw/` 안에 있는지 확인한다. 밖에 있으면 사용자에게 옮길지 묻는다.
**직접 옮기지 않는다** — `raw/`는 사용자 소유다.

바이너리(hwp/xlsx/pptx/pdf)는 텍스트를 먼저 추출한다. 이미지가 포함된
마크다운은 텍스트를 먼저 읽고, 필요한 이미지만 따로 본다 — 한 번에 못 읽는다.

### 2. 요점을 먼저 논의한다 — 건너뛰지 않는다

읽고 나서 **핵심 요점 3~5개를 사용자에게 제시하고 방향을 받는다.**
무엇을 강조할지, 어느 도메인으로 분류할지, 기존 무엇과 엮이는지.

여기서 방향이 어긋나면 이후 10여 개 페이지가 전부 어긋난다.
사용자가 "알아서 해"라고 하면 그때 진행한다.

### 3. source 페이지 작성

`wiki/sources/`에 자료 하나당 한 페이지. 형식은 볼트 스키마 참조.
원본 경로를 반드시 기록한다 — `raw/`는 git에 없으므로 경로가 유일한 연결고리다.

### 4. 개체·개념 페이지 갱신 — 여기가 본체다

자료에 등장한 사람·조직·장비·시스템·제품 → `wiki/entities/`
기술·개념·방법론 → `wiki/concepts/`

각각에 대해:

- 페이지가 없으면 **만든다**
- 있으면 **등장 이력에 이번 자료를 추가**하고 내용을 갱신한다
- 새 정보가 기존 서술과 충돌하면 → 5번

이미 있는 페이지를 그냥 지나치는 것이 가장 흔한 실패다.

### 5. 모순 표시

새 자료가 기존 주장과 충돌하면 **양쪽 페이지 모두** `status: contested`로 바꾸고,
각 페이지에 충돌 지점과 상대 페이지 링크를 명시한다.

숨기거나 새 정보로 조용히 덮어쓰지 않는다. 어느 쪽이 맞는지 모를 때는
모른다고 쓴다.

### 6. index.md · log.md 갱신

`wiki/index.md` — 새로 만든 페이지를 해당 범주에 추가
`wiki/log.md` — 맨 아래에 추가:

```
## [YYYY-MM-DD] ingest | <자료 제목>

<무엇이 들어왔고 어떤 페이지가 영향받았는지 2~3줄>
```

### 7. 결과 보고

무엇을 만들고 무엇을 갱신했는지 목록으로 보고한다. 사용자가 Obsidian에서
바로 확인할 수 있게 한다.

## 빠른 참조

| 단계 | 산출물 |
|---|---|
| 1 | 자료 위치·형식 확인 |
| 2 | **요점 논의 — 사용자 승인** |
| 3 | `wiki/sources/<제목>.md` |
| 4 | `wiki/entities/*`, `wiki/concepts/*` 생성·갱신 |
| 5 | 충돌 시 양쪽 `contested` |
| 6 | `index.md`, `log.md` |
| 7 | 변경 목록 보고 |

## 흔한 실패

| 실패 | 결과 |
|---|---|
| 요점 논의를 건너뛰고 바로 씀 | 방향이 어긋난 페이지 10여 개 |
| source 페이지만 만들고 끝냄 | 위키가 아니라 요약 폴더가 됨 |
| 기존 개체 페이지를 안 건드림 | 상호참조가 안 쌓여 복리 효과 소멸 |
| 모순을 새 정보로 덮어씀 | 낡은 정보를 사실로 오인하게 됨 |
| `index.md` 갱신 누락 | 질의 때 못 찾음 = 없는 것과 같음 |
| `raw/` 파일을 수정·이동 | 진실 원천 훼손 |

## 중단 신호

다음이 떠오르면 멈춘다.

- "요점 논의는 생략해도 되겠지" → 2번은 필수 체크포인트다
- "개체 페이지는 나중에 만들자" → 나중은 오지 않는다
- "모순은 애매하니 일단 새 걸로" → 양쪽에 표시하고 사용자에게 알린다

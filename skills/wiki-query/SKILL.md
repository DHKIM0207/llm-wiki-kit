# 위키 질의 (Query)

## 볼트 찾기

1. 세션 컨텍스트의 `LLM 위키 볼트:` 줄(플러그인 SessionStart 훅이 주입하거나 CLAUDE.md에 있음) → 그 절대경로
2. 없으면 `~/.claude/llm-wiki/vault-path` 파일 첫 줄
3. 없으면 현재 디렉터리가 볼트인지 — 루트에 `AGENTS.md`(또는 `CLAUDE.md`)와 `wiki/index.md`
4. 모두 아니면 멈추고 `wiki-init`을 권한다

이하 `<VAULT>`는 그 절대경로다. 볼트 밖에서도 호출되므로 **모든 경로를 절대경로로 쓴다.**

## 핵심 원칙

**인덱스를 먼저 읽고, 페이지로 파고들고, 인용과 함께 답한다.**
그리고 좋은 답변은 위키에 되돌려 넣는다.

되돌려 넣지 않으면 사용자의 탐색 결과가 채팅 기록 속으로 사라진다.
질문 하나하나가 위키를 풍부하게 만들어야 한다.

## 언제 쓰지 않는가 — 소음 방지 게이트

억지로 위키를 뒤지지 않는다. 다음이면 그냥 답하거나 바로 작업한다:

- 위키와 무관한 일반 지식 질문 (문법, 라이브러리 사용법 등)
- 위키에 축적됐을 리 없는 일회성·즉석 작업
- 사소한 단순 조회

반대로 **먼저 참조한다**: 과거에 풀었을 법한 문제 · 이 환경 고유의 함정 ·
특정 시스템·서버·설비·과제 · 예전에 내린 설계 결정을 다시 건드릴 때.
애매하면 `index.md`만 훑어 관련 페이지 유무를 빠르게 판단한다.

- 새 자료를 넣을 때 → `wiki-ingest`
- 위키 건강 점검 → `wiki-lint`

## 절차

### 1. index.md 먼저

`<VAULT>/wiki/index.md`를 읽어(또는 좁은 조회면 그 안에서 grep해) 관련 페이지를 추린다.
전체 위키를 grep부터 하지 않는다 — 인덱스가 그 일을 하라고 있는 파일이다.

```bash
grep -i "키워드1\|키워드2" "<VAULT>/wiki/index.md"   # 인덱스 안에서 좁히기
```

인덱스에서 못 찾으면 그때 `wiki/` 전체 검색. 그리고 찾았다면 **인덱스에 누락이
있다는 뜻이므로 고쳐둔다.**

### 2. 페이지를 읽고 링크를 따라간다

추린 페이지를 읽고, 그 안의 `[[링크]]`와 `sources`를 따라 한 단계 더 들어간다.
개체 페이지 → 근거 자료 페이지로 내려가는 경로가 대부분의 답을 만든다.

### 3. 인용과 함께 답한다

**근거 없는 문장을 쓰지 않는다.** 각 주장에 출처 페이지를 링크로 단다.

위키에 없는 내용을 모델 지식으로 채워 넣지 않는다. 모르면 모른다고 하고,
어느 자료를 수집하면 답할 수 있는지 제안한다.

`status: contested` 페이지를 근거로 쓸 때는 **모순 상태임을 답변에 명시한다.**

### 4. 되돌려 넣을지 제안한다

답변이 다음 중 하나면 `wiki/syntheses/`에 남길 것을 제안한다.

- 여러 자료를 종합해 만든 결론
- 비교표
- 이전에 없던 연결 관계를 발견
- 사용자가 다시 물어볼 법한 것

제안이지 강요가 아니다. 승인하면 볼트 스키마(`<VAULT>/AGENTS.md`)의
`synthesis` 뼈대대로 쓰고, **`index.md`·`log.md`를 반드시 갱신한다.**

```
## [YYYY-MM-DD] query | <질문 요지> → syntheses/<페이지>
```

단순 사실 조회("그 서버 IP 뭐였지")는 남기지 않는다.

## "개발·개선할 것 있나?" 질문

`wiki/ideas/`를 본다. 이 질문은 위 절차와 다르게 다룬다.

1. `targets` 프론트매터로 대상 시스템을 거른다 — "○○ 쪽"이면
   `[[○○]]`을 `targets`에 가진 것들
2. `stage`가 `완료`·`보류`인 것은 기본으로 빼고, 요청하면 보여준다
3. `priority` 순으로 제시하되, **각 항목의 "현재 상태" 확인 시점을 함께 말한다**

3번이 중요하다. 아이디어는 코드가 바뀌면 낡는다. 몇 달 전 확인 시점이면
"이 서술은 <커밋> 기준이라 지금은 다를 수 있다"고 붙인다.

```bash
cd "<VAULT>"
grep -l "대상-시스템" wiki/ideas/*.md               # 대상별
grep -rn "^stage:" wiki/ideas/ | grep -v 완료      # 진행 중인 것
```

새 아이디어가 대화 중 나오면 **`wiki/ideas/`에 남길지 제안한다.**

## 출력 형식

질문에 맞는 형태를 고른다. 기본은 대화 답변이고, 요청이나 성격에 따라:

| 형태 | 언제 |
|---|---|
| 마크다운 페이지 | 종합 결론을 남길 때 |
| 비교표 | 선택지가 3개 이상일 때 |
| Marp 슬라이드 | 발표 자료가 필요할 때 |
| 차트 | 수치 추세를 보여줄 때 |
| Obsidian 캔버스 | 관계 구조를 보여줄 때 |

## 흔한 실패

| 실패 | 결과 |
|---|---|
| 인덱스 안 읽고 전체 grep | 느리고, 인덱스 누락이 방치됨 |
| 출처 없이 답변 | 나중에 검증 불가 = 신뢰 못 함 |
| 위키에 없는 걸 지식으로 채움 | 위키 내용과 모델 지식이 뒤섞여 오염 |
| `contested` 페이지를 확정 사실로 인용 | 사용자가 낡은 정보로 판단 |
| 무관한 작업까지 위키 조회 | 소음·토큰 낭비 (게이트 무시) |
| 좋은 종합을 채팅에만 남김 | 복리 효과 소멸 — 이 위키의 존재 이유가 사라짐 |
| 상대경로 사용 | 볼트 밖에서 호출되면 엉뚱한 곳을 봄 |
